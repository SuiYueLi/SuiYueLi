本应用在日历之上附加了笔记功能，可用于在日期上标注历史事件，也可用于记录个人笔记。

记笔记之前请务必先尝试导出节庆民俗列表或每年重复日列表，确保数据在当前浏览器中可正常导出。

笔记带有可选用的附件功能，只在桌面端 Chromium 系浏览器（Chrome、Edge 等）中完全支持。

笔记基本用法

点击主界面右下角 ⊕ 按钮，即可在当前选中日期新建笔记。

当前选中日期的笔记在主界面下部笔记栏内列表显示。点击笔记条目展开笔记，点击其右上角悬浮的 ✎ 按钮进入编辑界面。

每条笔记可设定一个字符图标，默认为 ✑；有附件的笔记默认为 📎。每日排首位笔记的图标会显示在日历格右上角。

笔记存储按岁（纪年）、花甲积日两级组织，单条上限 8000 字。

从汉堡菜单链接进入【笔记总览】页，可浏览指定华夏纪年区间的笔记。该页也提供筛选和批量操作。

附件功能

每条笔记可附加本地文件引用（不复制原件）。添加附件后，笔记展开状态顶部、编辑页底部会显示缩略图栏，点击缩略图可浏览原件。

支持添加的附件类型：

  • 图片 - 浏览时支持缩放与拖动平移；
  • 视频 - 使用浏览器内置播放器；
  • 音频 - 使用浏览器内置播放器；
  • 文本 - 以只读方式显示内容（最大 16kB）；
  • 其他 - 不可在应用内浏览，只显示类型图标。

附件原件始终保留在原位置，应用不会对其进行复制、移动或修改。

附件缩略图维护可在【存储与导出】页设置。

本地同步与文件夹

在桌面端 Chromium 系浏览器（Chrome、Edge 等）中，可指定一个本地文件夹作为本地目录。指定后：

  • 笔记自动以 JSON 格式同步保存在该目录下的分段结构中；
  • 附件浏览可直接访问原文件，无需每次授权；
  • 缩略图在本地目录的 .thumbnails 文件夹内镜像备份。

本地同步保存属于单向备份。建议不要直接编辑本地文件，编辑后未经导入会被应用的下次存储动作覆盖。

指定文件夹后，还可通过「本地笔记文件分割」管理分段节点，将笔记按岁段拆分为多个 JSON 文件。

原子保存机制

浏览器保存本地文件采用原子保存机制：按 createWritable → 写入 → close 三步流程，在 close 完成前不会替换磁盘上的原文件。优点是即便写入过程中遇到断电、浏览器崩溃等异常，已保存的旧版本仍保持完整，不会出现半写入的损坏文件；缺点是每次保存都是新建文件替换旧文件，文件的创建日期总是与修改日期一同更新。

针对原子保存机制，笔者采取了分割本地笔记文件的策略——将所有笔记按岁段拆分为若干独立分段，每次保存仅重写受影响的分段。这样既可以降低写入失败影响面、提升读写性能，也将每次的文件替换控制在单一分段。

本地笔记文件默认分割为今岁前、今岁、今岁后三段，今岁段在跨年后会随之后移。

三级标题与时间戳格式

### `图标` 片段 [类型图标...]
`[created | updated]`
  • `图标` - 反引号包围的单字符图标，缺省 ✑。
  • 片段 - 笔记内容开头片段，截至15字符或第2个回车。
  • 类型图标 - 附件类型图标按首次出现顺序去重，不带数量（如 🖼️📊）。
  • `[created | updated]` - 反引号包围，方括号内为时间戳，格式 HJ积日数.hhmmss（兼容旧格式毫秒时间戳，纯整数）。
  • 导入时识别时间戳（通过有无小数点区分新旧格式），识别失败将被跳过（完成后列出失败行号）。
  • 导入兼容旧格式 ### "片段" `图标 [created | updated]`。
  • 附件区段会被解析并写入 assets 字段，但 TXT 格式不携带 thumbKey 与 size，这两个字段在导入后为空（size 为 0）。若同时导入缩略图包，应用会通过其中的 manifest.json 自动补全这些字段；否则需通过缩略图维护重新生成。

缩略图包

导出笔记时勾选「导出所含缩略图」会生成独立的 zip 文件（命名 岁月历_缩略图_<时间戳>.zip），不论导出的笔记格式为 JSON 或 TXT，缩略图包均包含：

  • <thumbKey>.webp（或 .png）- 缩略图文件；
  • manifest.json - assets 信息表，记录每个 thumbKey 对应的附件元数据（type、name、path、size、mime）。

导入时连同笔记文件一起选择即可自动写入 IndexedDB；同时应用会使用 manifest.json 补全笔记 assets 中缺失的 thumbKey、size、mime、type 字段（已有 thumbKey 的 asset 不覆盖）。

笔记导入校验

  • 合并导入时将检测同日笔记中创建时间戳相同的项，冲突时弹出列表供处理（单文件与多文件批量导入流程一致）。
  • JSON 文件须符合其格式规范，导入时会对字段进行规范化（缺失字段以默认值补全）。
  • 每条记录中，未标注"可选"的字段不可省略。
